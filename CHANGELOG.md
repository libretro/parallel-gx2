# Changelog of the libretro core

What changed in the libretro core of this fork, newest first. Changes that come with a merge of upstream Cemu are in upstream's own history; a merge is noted here with the upstream version it brought in.

## Unreleased

- XML documents (settings, controller profiles, the title list cache, account and online service replies) are held as a tree in C (`xml_tree.c`) over libretro-common's rxml, where each element was a C++ object with strings and vectors of its own; `xml::Document` and its handles are a thin layer over it, and freeing a document walks it without recursing. Every document reads, changes and writes as before: a check against the old layer on 600,000 altered documents, edited and written back, found no difference. NEX's HMAC-MD5 is C (`hmac_md5.c`) over libretro-common's MD5, and the core's own MD5 is gone.
- Graphic packs' rules.txt, game profiles and a WUHB's meta.ini are read by an ini reader in C (`ini_file.c`), which parses a file once into one allocation, where the C++ reader copied it into a vector and kept each section's options in a vector of their own; `IniParser` is a thin walk over it, and the meta.ini reader in `title_xml.c` uses it rather than a copy of its rules. Every file reads as before: a check against the old reader on over a million altered rules.txt files found no difference. The RPL loader's CRC-32 is libretro-common's, and the core's own CRC-32 code is gone.
- A title's meta.xml, a WUHB's meta.ini, and a title's app.xml and cos.xml are parsed in C (`title_xml.c`), on libretro-common's XML reader and CRC-32, into plain structs, where each was parsed into C++ strings, arrays and a document tree; `ParsedMetaXml` and `ParsedCosXml` are thin wrappers that free them. Every name and number is read as before, the meta.ini's title id included (its 0005000F and the CRC-32 of author, longname and shortname): a check against the old readers on about five million altered files found no difference. Two things the old readers did wrong are gone: a meta.ini with no author, longname or shortname read an option that was not there, where now the missing one counts as empty; and a meta.xml whose title_id, or an app.xml with a field, that is not a number (or is too big for one) threw an exception nothing caught, where now the meta.xml is turned away as having no title_id and the app.xml field reads 0.
- Disc images and title folders are opened in C (`fst_open.c`): a disc's partition table, its SI and GM partitions and the GM partition's ticket, and a title's TMD, ticket and content files, where `FSTVolume` did it with the C++ TMD and ticket parsers. A partition whose header has the wrong magic is now turned away, where one whose sector size field happened to be right was taken. `FSTVolume::OpenFST` is gone, and `FST.cpp` wraps the C.
- `dependencies/curl-compat`, a C++ stand-in for libcurl's API, is gone. The core's HTTP transfers run in C (`src/Common/http_xfer.c`) on libretro-common's `net_http` and TLS client, on one transfer thread with no locks; the online services' requests (`napi_helper.cpp`, Miiverse, BOSS) use it directly, and nlibcurl - the console's libcurl, which games call - has libcurl's behaviour over it in C (`curl_host.c`). A Miiverse community upload no longer leaks its form, and a request that is retried no longer keeps what the failed attempt received.
- A disc image's or title's files are read in C (`fst_volume.c`): the FST decrypted and parsed, the block caches, the decryption, and the checks against the hashes a hashed cluster carries and the content hashes a title's TMD gives a raw one. The volume is one allocation besides its caches, with no C++ objects in it. A raw content whose size is not a whole number of 32 KiB blocks is now hashed to its end, where its last part was hashed from past the block it was read into. The unused content-file verifier is gone.
- A `.wua` held by a title is shared through C (`zarchive.c`): a title that mounts an archive another already holds takes it with no writer's turn and no copy of the table of shared archives, and one that gives it back while others hold it changes only a count; the table is replaced only when an archive is opened or closed. An archive asked for while its last holder was closing it is opened anew rather than handed out as it closes.
- Files read whole (the title list, meta.xml files, keys, caches) are read through C (`mapped_file.c`): lent from their mapping, or read once where they cannot be mapped, as before, without a C++ stream object or vector in between.
- A disc image's or title's file table is looked up in C (`fst_table.c`), parsed once into one allocation, where it was three C++ vectors. Opening a file in one no longer builds a path object for the lookup, and a listing no longer goes through the C++ entries. A table with a folder that ends at or before itself is now turned away when the image is opened, where listing that folder, or looking a name up next to it, went round for ever; a read of a file in an unhashed cluster no longer reads past the file's end when the offset and the length of the read together overflow 32 bits.
- Disc keys are read and tried by C (`key_cache.c`): keys.txt is read from its mapping, where it was read a line at a time into a string; a `.key` file beside an image is read without a buffer the size of the file. The cell the key set, the title list and the emulated controllers are kept in without a lock is C too (`rcu_cell.c`), the same cell as before.
- A Wii U archive (`.wua`) is read by a reader in C. A game listing a folder in one no longer has every name in the folder copied into a string of its own when the folder is opened: the names are read one at a time as the listing goes. A file it opens no longer opens a stream of its own the first time it is read where the archive cannot be mapped; the archive keeps a few and lends one to each read. A title whose archive failed to mount no longer keeps a pointer to the archive it gave back, and a mount that fails no longer closes an archive or bundle another mount of the same title still reads. Miiverse's offline posts are opened without a lock.
- What disc images and a title's `.app` files are read through for decryption is now C (`fst_source.c`), where it was a C++ class for each kind of file. Nothing changes in how they are read.
- Disc images and title content are decrypted with libretro-common's AES, which runs on the CPU's AES instructions on ARM too (Android, Apple silicon, Linux on ARM), where the core's own AES fell back to a software table implementation. On x86 it decrypts several blocks at once, about a third faster for a 64 KiB block than before. A CTR stream whose length is not a whole number of blocks (BOSS data, NFC tags) no longer writes past its end.
- A homebrew bundle (`.wuhb`) is read by a reader in C. A game opening a file in one no longer builds a path object and a string for each part of the file's path. Listing a folder in one no longer allocates a string for each entry: the name is read straight into the listing. A name longer than the listing holds is cut and ended rather than left without its end.
- Disc images (`.wud`, `.wux`), a title's `.app` files and homebrew bundles (`.wuhb`) are read through one small reader in C over libretro-common's filestream, where each had a C++ stream pool of its own. A file that cannot be mapped keeps a few streams and lends one to each read; mapped, nothing changes. A `.wux` whose header gives an image size its file has no room for is refused when opened, where its sector table was read past its end.
- The title list takes no lock: looking a title up, starting one and the system's own title lists read the list in place from any thread, and a scan puts a new list in place of the old one. A scan asked for just as the last one finished is no longer lost, and waiting for it no longer hangs. Closing the core waits for the title cache to be written rather than leaving it half written. From the second title started in a session, the titles the system lists to a game are mounted where it is told they are, as they were for the first. Listing them no longer allocates. The save list, which nothing in the core used, no longer walks every save folder on each start.
- Loading a title takes no lock either. The disc keys from keys.txt are read whole into a set that a search reads in place and a reload replaces whole, where every search and every reload took the key cache's mutex; the key files beside an image are tried for that image only rather than added to the cache. A `.wua` opened by more than one title (a game, its update and its DLC in one archive) is shared through a table replaced whole, where the archive pool took a mutex for each title mounted and unmounted.
- The file system takes no lock. Every file a game opened, read, wrote or closed, and every look into the mounts, went through one lock shared by the whole emulator, so the IOSU thread reading a file, a CPU thread loading a module and the title conversion all waited on each other. The mounts are now a table that is never changed in place: mounting or unmounting makes a new one and swaps it in, and one replaced is freed once nothing reads it. What the disc images and title content files are read through is safe to read from any number of threads at once: each reader of a disc or title volume is lent a block cache of its own from a small pool, and a file that cannot be mapped (one only the frontend's VFS reaches) lends each reader a stream of its own.
- A `.wua`'s readers are kept and lent: each lookup made a reader of its own and threw it away, and each file a game opened made one with its own Zstandard decoder and two 64 KiB buffers the first time it was read. The archive now keeps a few, lent to whatever looks up, lists or reads and given back after, with no lock, so a game opening files makes none once there is one free, and a block one file decoded is there for the next read of it. A title's boot movie and boot logo are read straight into where the system keeps them, not into a buffer of their own first.
- Disc images and titles kept as .app files are read without allocating: the decrypted blocks are kept in a fixed set of slots made at the first read, where each block not yet kept made an entry in a map, and blocks of the other kind were freed and allocated again. A read of more than one whole block has those blocks decrypted straight into where the game wants them, rather than into the cache and copied out of it. A file more than 4 GiB into its section of a disc read from the wrong place (its position was worked out in 32 bits), and a read in a hashed section did not stop at its file's end.
- Starting a title no longer reads its executable a second time when it has no update: the hash of the executable without its update was taken by reading the whole file again (decompressing it again from a `.wua`) into a buffer of its own, even when it was the same file. Now the hash is taken over again only when an update or graphic pack gives a different executable, and then a piece at a time through one small buffer. A graphic pack's rules.txt and patches, a title's title.tmd and title.tik, and the ticket a game asks for its DLC are read from the file's mapping instead of copied out first.
- Directories are made, listed, removed and renamed through libretro-common's VFS on every platform, like the files in them, where std::filesystem went around it: a path only the frontend reaches (Android's content:// URIs) now works for the save, title, account, cache and graphic pack folders too. A game listing a save folder reads each entry's name, type and size as the directory read gave them, with nothing allocated per entry. Removing a folder no longer goes into a link to a folder elsewhere.
- A disc image's key is looked for in every file in the image's folder whose name ends in `.key`, so the `game.key` a dumper writes beside `game.wux` is found without renaming it; keys.txt is read again at every load, so a key added to it counts without restarting RetroArch. When no key fits, the message says which key files were tried, which ones are not keys at all, and how many keys keys.txt holds (the example it is created with not counted).
- Game images are read from their mapping: a `.wua`'s index and blocks, a `.wud`'s or `.wux`'s sectors (the `.wux` sector table where it lies, not copied), a title's `.app` files and a `.wuhb`'s entries and files. An encrypted block is decrypted straight from the file's pages into the cache that keeps it, where it was first read into that cache and then decrypted there; a file read from a `.wua` no longer opens a stream of its own, and one from a `.wuhb` no longer allocates its entry's name on every read. A file only the frontend's VFS reaches is read as before. A `.wuhb` hash chain that loops no longer hangs a lookup.
- The files the core reads to use - the title list, save and title meta.xml, game profiles, controller profiles, saveinfo.xml, amiibo and NFC tag dumps, private keys, disc keys, graphic pack shaders - are read from the file's mapping, without a copy of the file in between: an XML file was read into a buffer and copied again into the parser's own, a graphic pack shader a character at a time, a controller profile three times over. Checking that a certificate file is there no longer reads it. The files the core writes - accounts, the title list, the save meta files, controller profiles, settings - go through libretro-common's filestream in one write each, settings and the title list into a file beside the old one that then takes its name; account.dat, persisid.dat and the language and country lists are written with '\n' line ends on Windows too, as they were elsewhere, which every reader of them takes.
- Every file the core reads and writes goes through libretro-common's filestream, on every platform. A path the core can open itself is opened by libretro-common's own implementation, where a file can be mapped and lent rather than read; only the paths the frontend alone can reach (Android's content:// URIs) go through the frontend's VFS (vfs_hybrid), where every file went through it before, mapped or not. The core's own three file layers - std::fstream on Linux and macOS, Win32 on Windows, and a wrapper over the frontend's VFS - are gone. A line is read by looking for its end in the mapping or the read-ahead, not a byte at a time.
- The shader and pipeline cache files are read without a lock and without a read buffer. A shader compile thread, or the GPU thread compiling a shader itself on a first play, looked an entry up under the cache's mutex and held it while another thread's write or read went to disk; now every change to the file is made by one writer thread, and a reader finds the entry in what that thread has published and inflates it straight from the file's mapping into its own buffer.
- Vulkan: with Async Shader Compile on, a draw that may not be skipped is no longer skipped because an earlier draw of the same pipeline could be. Such draws (full-screen passes into textures the game keeps, mostly) were dropped for as long as the earlier draw's compile ran, which could leave what they draw wrong for the rest of the scene. Now one compiles the pipeline itself when no compile thread has started on it, or waits for the one that has. A pipeline whose shaders are dropped while its compile is queued no longer leaves that compile to run with them gone.
- Vulkan: a copy between a depth and a color surface no longer compiles its pipeline while the copy waits. The pipeline that copies into a format is made on a pipeline compile thread when the first texture that can be drawn to in that format is created, and the copy shaders when the renderer starts, so the copy finds them ready. Before, the first copy compiled the shaders, and the first copy into each format its pipeline.
- Closing content no longer crashes RetroArch on Linux (SIGABRT, from the core's GPU thread). The GPU thread ended itself with pthread_exit, which on glibc unwinds the thread's stack as an exception the C++ runtime may not stop - and the runtime the core links into itself ends any thread whose unwind reaches its entry that way with abort(), every time a title was closed. The thread now unwinds to its own entry and returns from there, running every destructor on the way, on every platform but Windows, which is unchanged.
- Vulkan: fewer pipeline compiles in gameplay on GPUs with graphics pipeline libraries (VK_EXT_graphics_pipeline_library with fast linking: current NVIDIA, AMD and Intel drivers). A pipeline is put together from four parts compiled once and shared by every pipeline that has them; a new pipeline whose parts were all compiled before is linked instead of compiled, and its optimized version is compiled in the background and swapped in. The first pipeline for each new shader still compiles its parts. Without the extension nothing changes.
- Vulkan: fewer pipelines on GPUs with VK_EXT_extended_dynamic_state and _2. The primitive topology (lists, strips, fans) and primitive restart are set with each draw, so the same shaders drawing triangle lists, strips and fans share one pipeline. Without the extensions nothing changes.
- Vulkan: fewer pipelines on GPUs with VK_EXT_vertex_input_dynamic_state (NVIDIA, AMD, Intel and recent mobile drivers). Vertex buffer strides and attribute offsets are set with each draw instead of baked into the pipeline, so the same shaders drawing from differently laid out vertex data share one pipeline. Rasterizer discard no longer splits pipelines on GPUs with VK_EXT_extended_dynamic_state2. Without the extensions nothing changes.
- Vulkan: fewer pipelines on GPUs with VK_EXT_extended_dynamic_state2 (most desktop and many mobile ones). Whether polygon offset applies and whether a draw is rasterized at all are set with each draw instead of baked into the pipeline, so decals, shadow passes and depth-only passes drawn with the same shaders as the rest share their pipelines. Without the extension nothing changes.
- Vulkan: fewer pipelines on GPUs with VK_EXT_extended_dynamic_state3's blend states (recent NVIDIA, AMD and Mesa drivers). Which render targets blend, how, and which channels are written are set with each draw instead of baked into the pipeline, so the same shaders drawn with different blending - the most common reason a title compiles another pipeline - share one. Without the extension nothing changes.
- Vulkan: fewer pipelines again, on GPUs with VK_EXT_extended_dynamic_state (most desktop and many mobile ones). The cull mode, front face, depth test, depth write, depth function and the stencil test and its operations are set with each draw instead of baked into the pipeline, so a title's shaders drawn with different depth, stencil or culling settings share one pipeline where each combination was compiled, and stuttered, on first sight. Without the extension nothing changes.
- Vulkan: fewer pipelines to compile. The stencil reference, compare mask and write mask are set with each draw instead of baked into the pipeline, so a game that steps its stencil reference (shadow volumes, masks, portals) compiles one pipeline for them where it compiled one per value, each a stutter on first sight. A pipeline that drops rasterizer discard for the viewport's X offset (GX2SetSpecialState) is no longer shared with one that keeps it.
- Vulkan and Metal: the pipelines loaded from the pipeline cache at boot are the pipelines the cache recorded. Built on a compile thread, a pipeline took its depth test, depth write, stencil, depth clip and rasterizer discard state from whatever the GPU thread was drawing at that moment instead of from the state stored with it, and was then used for draws that wanted the stored state - wrong depth or stencil wherever such a pipeline was picked. Metal keyed its pipelines on the live primitive type the same way.
- Vulkan: RetroArch's low-latency modes (NVIDIA Reflex, AMD Anti-Lag) work with this core. The core made its Vulkan device itself, with the extensions the frontend required and none it could use where the GPU has them, so VK_NV_low_latency2 was never on it. With a frontend that takes version 2 of the context negotiation the device is now made through the frontend's own call, which adds those; an older frontend gets version 1 as before.
- Loading a title's shader and pipeline caches no longer allocates and clears a quarter of a megabyte for every entry. Each cached shader and each cached pipeline was rebuilt in a register file of its own, 256 KiB, made and zeroed for it and thrown away after - several gigabytes of clearing memory for a large cache. A thread now keeps one and reuses it. A cached pipeline whose shader was no longer in the shader cache leaked its register file and the pipeline each time.
- XML is read and written with libretro-common's rxml in place of pugixml and tinyxml2, which are gone from the tree (the pugixml submodule with them). The settings, controller profiles, title list cache, saveinfo.xml and the online services' replies go through one small layer on it. A file as tinyxml2 or pugixml wrote it reads as before. A saveinfo.xml with an account that had no timestamp no longer gets an empty one.
- Dear ImGui is gone from the tree, with the drawing the core did through it, none of which reached the screen: RetroArch gives the core no window of its own, so every imgui frame - the loading screen, the error and keyboard dialogs, the friend notifications, the performance overlay - was built every frame and thrown away. The notifications (a friend coming online, say) and a title's error dialogs now go to RetroArch's on-screen messages instead; an error dialog asks for A or B there and takes the answer from the controller, where before it sat waiting on a button nobody could see. The FontAwesome font embedded for imgui (160 KB) goes with it.
- Fast-forward, slow motion and frame advance work: RetroArch's frames are the core's clock. Each retro_run moves the Wii U's time on by one frame, its vsyncs and its audio with it, and the time stands still between them, as in the cores that count cycles; when every emulated core and the GPU have nothing to do, the time goes straight to the next thing due - an alarm, AX's next audio frame, the vsync - so a frame takes as long as its work, and fast-forward runs as fast as the machine can. The core no longer paces itself by the wall clock: the vsync timer, the audio grant from the time between retro_runs and the cores running on for 100 ms after the frontend stopped asking are gone. A device too slow for the title's rate now slows the game down, sound included, as other cores do, instead of keeping its audio at real time.
- The games' movies (h264.rpl) are decoded by RetroArch's H.264 decoder - on the GPU through Vulkan Video or D3D11 where RetroArch has it - or, where it has none, by libretro-common's rh264 in the core. ih264d is gone from the tree. The decoder takes no lock: what the game queues reaches the decoder thread, and what it decodes reaches the game, through lock-free queues, and the thread sleeps until there is something to do. Each picture still lands in the buffer of the input that coded it, with the coded size and crop rectangle the console's decoder reports, through B-picture reordering; an input that makes no picture is answered at once, where a stream the old decoder could not take left the game waiting for good.
- The GamePad's sound is mixed onto the TV's with the same moment of each. It was mixed in a group of frames (12 ms) late, so a game playing the same sound on both - Bayonetta 2's music, for one - was heard together with a copy of itself 12 ms behind: a comb filter that took a notch out every 83 Hz, and the sound came out thin and hollow. Surround 5.1 mixed down to stereo (when RetroArch has no multi-channel output) is rounded to the nearest sample value rather than cut toward zero.
- Breath of the Wild's `.wua` starts: its title's meta/meta.xml was not found, and loading stopped with "its meta/meta.xml is unusable". The archive's meta/ folder is not in name order, and holds meta.xml twice, first and last, as archives made by tools other than Cemu's can; the reader looked names up by halving each folder, which needs them sorted. It now goes through a folder in its order and takes the first match, as Cemu does, so every archive Cemu opens opens here.
- Content the core cannot start says why, in RetroArch's log and on screen, where it said "Unsupported file format" for everything. A `.wua` that does not open gives what its last bytes hold instead of an archive's footer (and the file size against the size the footer records); one that opens but holds no base title lists what it holds; a title without its meta, app or cos .xml names the one missing; a meta.xml that cannot be used says whether it is missing, not XML (and where it stops parsing), or without its <menu> or title_id, with its first bytes in log.txt.
- RetroArch no longer crashes a few seconds after a title fails to start (seen with Breath of the Wild on Windows, as an access violation in no loaded module). The core measures the TSC's rate for three seconds after its first frame, on a thread it left running on its own; when RetroArch unloaded the core in that time, the thread woke in code that was no longer there. The measurement is now stopped and its thread joined before the core is unloaded, and the rate measured until then is kept.
- A checkout without its git submodules (a clone made without `--recursive`) builds: make fetches them on its first run, where the build stopped at glm/glm.hpp. `NO_SUBMODULE_FETCH=1` leaves the checkout alone.
- Vulkan: a pipeline compile no longer waits for the driver's pipeline cache to be saved. Every compile took a lock the save held for as long as the driver took to hand the whole cache over, so a pipeline the GPU thread needed at once - a stutter already - could stall for that long on top. The save now picks a moment no compile is under way, and a compile starting during it goes ahead. The cache is written when its contents changed (it was written whenever its size changed, and not when only its contents did), through a file that takes its name only once complete, so a crash during the write no longer leaves a broken cache. It is read by mapping the file instead of copying it into memory first.
- The Windows build with MSYS2's make runs again: the precompiled header's stub named the header by the absolute path make gave it, a /c/... one MinGW's g++ cannot open. It now finds the header through the include path, and a tree built before picks the new stub up by itself.
- The shader and pipeline cache files no longer search their whole file table on every read and write. Finding an entry looked at every entry before it, and writing one looked at the whole table two or three times over - to find its name, a free entry and room for its data, the last again and again until a gap fitted - so filling a cache got slower with every entry in it: writing 1000 entries looked at nine million table entries, now six and a half thousand. The table is indexed by name when the file is opened, its free space is kept in a list, and the table grows twice as big at a time instead of by 64 entries. Reading an entry no longer allocates a buffer of its own for the compressed bytes. The file format is unchanged; standalone Cemu reads what the core writes and the other way round.
- The semaphores the emulator's host threads wait on take no lock: an idle core waiting for a guest thread to become runnable, the H.264 decoder waiting for frames, the IOSU play-statistics service and the Vulkan pipeline cache each waited on a mutex and a condition variable, and every guest thread made runnable took that mutex to count itself onto its core's run queue. The counts are atomics and the waiters sleep on eventcounts. Closing content no longer waits up to a tenth of a second more than it has to for the scheduler's shutdown watchdog to notice the cores have stopped.
- The IOSU kernel, which every IPC a title makes passes through (file system, accounts, the network services), takes no lock: its message queues were guarded by one global mutex with condition variables per queue, its timers by a mutex and a condition variable, its command pool by a spinlock and its replies by a mutex per core. The queues are now lock-free with their senders and receivers sleeping on eventcounts, the timers belong to their own thread, which takes operations through a queue, and the device table, handles and command pool are published or claimed atomically. Two races went with them: two IOS_Open calls at once could be given the same device handle, and a core's IPC buffers were handed back by the service threads into a list only the core itself could safely touch. A closed handle is now closed by the time the core has its answer.
- The legacy IOSU devices (act, acp, mcp, nim, fpd, boss) take their requests without a lock: each device's queue was a ring under a global mutex with a mutex-and-condition-variable counting semaphore beside it, and is now a lock-free queue its one worker sleeps on. The shader cache's asynchronous writer likewise takes its jobs through a lock-free list and sleeps on an eventcount instead of a condition variable.
- Side by Side, Top Bottom and Both Screens: the GamePad screen no longer flashes black. Titles that scan out the GamePad less often than the TV (Wind Waker HD) left it black in every frame with only a TV picture, about twice a second; each screen now keeps its last picture until the title sends a new one, as a GamePad does. A frame also no longer blits the TV picture a second time when the GamePad's arrives after it, and on Vulkan the mouse cursor costs a copy only where the next frame leaves it uncovered.
- New screen layout Both Screens (Controller > Layout 1-5): the TV and the GamePad at their own sizes, the GamePad centred under the TV, or above it with GamePad Position Swapped. Unlike Top Bottom, neither picture is stretched. Touches count on the GamePad's part, on Vulkan and OpenGL. A frontend with video views (RetroArch's, libretro/RetroArch#19811) gets the two pictures as two screens and lays them out itself: one under the other or side by side, the GamePad in a window or on a display of its own, both on a headset, each with its own shader. The single-screen layouts go to it as one screen. Side by Side, Top Bottom and Picture in Picture look as before, except in the frontend's stereo modes and on a headset, where they become Both Screens.
- The arm64 cores (Linux, Android arm64-v8a, macOS, iOS and tvOS) and Android x86_64 build again with the Makefile. Since the static Makefile their links stopped: the x64 recompiler was built into arm64 cores next to the AArch64 one, and both define the same function; H.264 decoding brought in a selector for 32-bit ARM code that is not built; the crash handler's ELF symbol table, which Android cores link against though they never run it, was only in the Linux sources; and Apple arm64 linked the H.264 decoder's symbol aliases twice. Each recompiler backend is now built only for its own architecture.
- zlib and Zstandard are libretro-common's, deflate and rzstd, and the zlib and zstd submodules are gone from the tree: a checkout without them no longer stops at the graphic pack tool wanting zlib's sources. The shader and pipeline caches' entries are still Zstandard frames made with Cemu's dictionaries, so a cache goes between the core and standalone Cemu either way, as before. The console's own zlib (zlib125), which games call, runs on libretro-common's deflate too; its deflate() takes Z_PARTIAL_FLUSH, Z_SYNC_FLUSH and Z_FULL_FLUSH as no flush, the output following at the next block or at Z_FINISH, and logs the first time a game asks for one.
- Wii Remotes and the Pro and Classic Controllers are read without locks. Every pad read a game made took the input manager's reader lock, then each emulated controller's for every button and stick it looked at, each controller's settings mutex and the spinlock around its pressed buttons - while retro_run's thread took the same locks to write the frame's input. Which controllers there are and how they are mapped are now published copy-on-write and read with no lock; each controller's state and settings are published whole each time they change, through a seqlock no reader waits on; and its pressed buttons are a bitset instead of a list searched under a spinlock. That also ends the stick and trigger values being read while retro_run was writing them.
- Online (Pretendo): the nex thread no longer wakes a thousand times a second while services are connected, or five times a second while none are. It sleeps in `select()` on its services' sockets and a loopback wake socket, so a packet, a queued request or a newly registered service ends the wait at once; the protocol's own clocks (retries, pings, request timeouts, all a second or more) are looked at every 100 ms. The logins do the same, and registering for secure access no longer spins a host core at 100% for the length of a round trip. Its request and service queues take no lock.
- Vulkan: the shader compile pool takes no lock. Each queued shader is held in the queue by a ticket that whoever compiles it - a compile thread, the GPU thread when it needs the shader at once, or the shader's own destructor if it was never compiled - claims with one exchange, so nothing is taken out of the middle of the queue under a mutex any more; the compile state is atomic, and waiting for a compile sleeps on a shared wake. A shader destroyed while still queued no longer leaves the compile threads a pointer to freed memory, and one destroyed while being compiled waits for it.
- The worker queues no longer take a mutex for every item. GX2's event callbacks (several every frame), the thread deallocators, curl's workers and the pipeline cache writer each have one consumer, and push through a lock-free list it takes from in order; the two pipeline compile pools, with several consumers, use a lock-free ring with an overflow list past 1024 queued. A worker with nothing to do sleeps on an eventcount instead of a condition variable.
- Vulkan: loading a title's pipeline cache no longer serialises its compile threads on spinlocks. Every pipeline they built took one spinlock shared by all shaders to register with its shaders, another shared by all framebuffers, one around its `new` and `delete`, and one around the set of cached hashes; the shaders' and framebuffers' pipeline lists are now lock-free, the allocations need no lock, and the hashes go to the GPU thread through a lock-free list. The renderer's destruction queue, filled from the GPU thread and the compile threads, is lock-free on both sides too.
- The two locks the emulated CPU hit hardest are gone, both spinlocks every core took. Every guest time read (OSGetTime, the scheduler's alarms, mftb) now does its arithmetic on an epoch it reads without a lock, and only a refined TSC rate (or a changed timer speed) starts a new one, at the time the old one gives, so no time already counted moves. Every data cache flush the CPU reports to the GPU, down to each dcbf/dcbst the interpreter runs, sets a bit in a lock-free page set instead of a spinlocked hash of vectors searched linearly, and a page already reported costs three loads.
- AX no longer takes a lock every 3 ms to reach the audio output. The reader-writer lock around the audio devices is replaced by a gate that whatever plays through them passes with one atomic count, never waiting; only a title starting or stopping (or a Skylander portal coming up, which now goes through the same gate instead of none) waits for the players already in.
- Vulkan: retro_run no longer takes a lock every frame that could hold the frontend's thread behind a GPU submit. It handed the frontend's Vulkan interface over again each frame under an exclusive lock, which waited for any submit in flight - itself waiting for the frontend's queue lock. Handing over the same interface now does nothing, and only a changed one waits for the submits that took the queue lock through the old one. Submits no longer take a reader lock either.
- GamePad motion and rumble are handed between retro_run and the game's threads without a lock: the motion sample through a seqlock neither side waits on, the rumble requests through a lock-free list drained once a frame.
- log.txt is written without a lock. Every logged line used to take a mutex and write and flush the file while holding it, so the GPU thread and the emulated CPU's threads queued on each other whenever they logged - and a thread that crashed while it held the mutex left the crash handler waiting for it for good, with no crash log. Each line now reserves its place in the file and is written there directly, still unbuffered, so a crash report keeps its last lines as before. The local time in each line's stamp is also no longer read through the non-thread-safe `localtime`. Switching log.txt off waits only for writes already under way before it closes the file.
- The title scan that loading a title waits for on a cold cache, and Install Games' rescan, no longer finish up to a tenth of a second late: the wait sleeps until the scan says it is done instead of checking every 100 ms. The same for SpotPass (boss): a game waiting on a task no longer waits a tenth of a second at the least, and the daemon no longer wakes ten times a second with nothing to do. Closing content no longer waits on millisecond polls for the IOSU workers and the SpotPass daemon to leave, nor eShop (nim) on half-second ones for the accounts.
- Audio Thread: with nothing buffered, the pull from RetroArch's audio thread slept a fixed millisecond, so audio that arrived just after it went out up to a millisecond late. It now waits only until AX's next block arrives (a millisecond at most, as before), and a frontend stopping its audio thread no longer waits that millisecond out.
- Closing content, or losing the graphics context, on Vulkan: the waits for the GPU thread to reach the pause gate, park there and hand the context back end the moment it does, rather than up to a millisecond later on each of them.
- Vulkan: the GPU thread no longer keeps a CPU core busy while it waits for the game's next commands. Upstream Cemu spins there, for as long as the emulated CPU takes, which on a four-core phone is a core the emulated CPU's own threads compete with, and power and heat on any device; it now sleeps until the commands are submitted, after the short spin that keeps a command that follows closely as quick to pick up as before. A game copying a surface no longer spins either, while the GPU thread does the copy.
- Loading a title no longer waits on a series of clocks: the GPU thread's start, the title starting, the graphic packs, the GPU's init and the IOSU services' threads were each checked every 1 to 50 ms, and the services alone cost 10 ms apiece. Each wait now ends the moment what it waits for has happened. Vulkan: the GPU thread no longer wakes a thousand times a second while a title waits to call GX2Init, nor sixty times a second before it starts, and a title stopped before it got that far no longer keeps the GPU thread waiting for it.
- Vulkan compiles its shaders with libretro-common's rslc in place of glslang, which is gone from the tree. The graphic packs' pixel shaders draw what they drew with glslang, pixel for pixel (checked on Mesa's lavapipe). The game's shaders now ask for 32-bit round-to-even arithmetic where the GPU offers it, as the decompiler always meant them to: glslang kept only the last of the 16, 32 and 64-bit requests, so none that applied.
- Wii U archives (`.wua`) are read and written with libretro-common's zar in place of the ZArchive library, which is gone from the tree. An archive's index is read into memory once when it is opened, so finding a file or listing a folder no longer touches the disk and no longer waits on another thread, and each open file reads through a reader of its own instead of every read of the archive queueing behind one lock. Convert to WUA writes archives standalone Cemu reads, and stops with an error when the destination cannot be written, where it used to carry on.
- The emulated controllers are updated once a frame, right after RetroArch's input is read, instead of by a thread of their own waking a thousand times a second to update them between frames, when nothing had changed.
- Vulkan goes through the frontend alone too: the core's own instance and device setup, its X11, XCB, Wayland, Win32 and Metal surfaces, its swapchain and the Breath of the Wild child-process workaround that came with them are gone - none of it ever ran under libretro, where the device, surface and swapchain are RetroArch's. Linux builds no longer need X11 headers, or any headers beyond the compiler's.
- Boot no longer waits up to three seconds for the CPU timer's calibration: a first estimate is ready 25 ms after the core loads and is refined in the background.
- The recompiler starts on a newly run function at once instead of at its next 10 ms look, so hot code spends less time interpreted, and its work queue no longer allocates.
- Vulkan: loading the pipeline cache no longer pauses 10 ms whenever 50 pipelines are queued, which held a warm cache to 5,000 pipelines a second; closing content no longer waits up to 250 ms for the pipeline cache's save thread.
- Audio goes to RetroArch straight out of the ring buffer, and AX's channels are converted straight into it: no copies on the way, and no 192 KiB flush buffer.
- The frame gate and the frame handoff between the GPU thread and `retro_run` take no locks.
- OpenGL goes through the frontend alone: the core no longer makes GL contexts of its own (WGL on Windows, GLX on X11, EGL on Wayland), links no GL, EGL or X11 library, and loads every GL function from RetroArch. Cemu's GPU thread runs as a cothread on RetroArch's thread, where its context is current, and the finished frame is blitted into RetroArch's framebuffer instead of read back into memory and uploaded again each frame. Wayland no longer has an OpenGL path of its own.
- Android: the fibers the emulated cores run on keep libco's state per thread (`LIBCO_MP`); without it a switch on one core could save its registers into another core's fiber.
- The core is now ParaLLEl GX2, `parallel_gx2_libretro`. RetroArch keeps core options, remaps and overrides under the core's name, so they start from the defaults: to keep them, copy RetroArch's `config/Cemu/` to `config/ParaLLEl GX2/` and rename the files in it from `Cemu.*` to `ParaLLEl GX2.*`. The core's own files stay in `<system>/Cemu/` and `<save>/Cemu/`.
- Online play (Nintendo Network, Pretendo, SpotPass, Miiverse) goes through the HTTP and TLS client RetroArch's libretro-common has, in place of libcurl and OpenSSL: the client certificates and the RSA/AES-256-CBC suite the console's services ask for included.
- Linux: content loaded a second time in the same RetroArch, after closing it, no longer crashes RetroArch. The core's OpenSSL read the system's `openssl.cnf`, which loads the pkcs11 engine on many distributions; that system library stays loaded when the core is unloaded and kept pointers into the first copy of the core, so the second load crashed in it. The core no longer has OpenSSL at all.
- A crash is no longer the core's to end: Cemu's crash handlers still write their crash log to `log.txt`, and then hand the crash to the handler there was before, where they used to end RetroArch at once (`_Exit` on Linux and Android, `exit(0)` on Windows), so the system's crash report (Android's tombstone, Windows Error Reporting) is written and names the fault. Ctrl+C and SIGTERM are left to RetroArch, which the core used to end on them (sco8487).
- New options Controller > Stick Dead Zone (Player 1) and (Players 2-4), 0% to 50%, 25% by default as standalone Cemu. The GamePad's sticks had no dead zone at all, so the slightest touch, or a stick resting a hair off centre, moved the character, while a Pro Controller had Cemu's 25% (demifiend9, Smash 4); now both follow the option, and sticks that rest at the centre can go lower (NNshi).
- Merged up to upstream Cemu 2.6-372 (29f2f1fa): coreinit alarm fixes and the alarm queue functions, recompiler entry speed-up and a function-scanning fix, the GamePad (DRC) audio mix fix, a GX2 flush fix and graphic pack patch-group fixes. The core reports upstream's version.
- GamePad touch screen: a tap or click lands where it is made. The core handed games the position in screen pixels where they expect the touch panel's raw values, as standalone Cemu sends them, so every touch landed in the lower-left corner (NNshi). With a mouse, an arrow cursor now shows over the GamePad picture while it moves, and hides after 3 s without movement or a tap elsewhere; Vulkan and OpenGL (sco8487).
- With the GamePad Screen layout, the picture is handed to RetroArch at the GamePad's own size (854x480, times the Internal Resolution, or a GamePad resolution pack's size) instead of stretched to the TV's 1280x720, so RetroArch's scaling and shaders get the GamePad's pixels. The other layouts stay at the TV's size (NNshi).
- Controller > Rumble Strength goes in steps of 10% (Off, 10% to 100%) instead of 25% (NNshi).
- Vulkan: a title's pipeline cache (`shaderCache/transferable/<title>_vkpipeline.bin`) is closed when the title is closed, instead of when the next one starts, so it is no longer left locked on Windows (NNshi).
- New option Core > Audio Thread (Restart), off by default: RetroArch takes the audio on its own thread and the Wii U's audio runs by the clock, as in standalone Cemu, so it no longer breaks up while a frame is late, during loading or shader compilation (NNshi). With it on, Vertical Sync rather than Audio Sync paces the frames, and RetroArch's audio statistics stay empty.
- Vulkan: no crash when a game's shader finished compiling in the middle of a run of draws. The first draw had skipped while it compiled (Async Shader Compile), and the next one found no descriptor sets and stopped the core on an assert; it now makes them (NNshi, The Wonderful 101).
- Core options rearranged (NNshi): categories System, Graphics, Controller, Title Manager, Core, Logging, then Graphic Packs and Cheats. Video and Shaders are now Graphics, Screen is Controller (with Rumble Strength and GamePad Motion), Content and Convert to WUA are Title Manager, the accounts are under System, and the core's own options (Internal Resolution, Render Ahead One Frame, Reduce BC1 Texture Memory) are under Core. Every option that applies only once the game is started again says (Restart) in its name; Graphic Packs and Cheats say it in the category's.
- CPU Mode, Accurate Shader Multiplication and Precompiled Shaders follow the game profile on Auto, as standalone: Auto used to override the profiles, which set the CPU mode for 27 games and turn accurate multiplication off for Super Mario 3D World, Captain Toad and Xenoblade Chronicles X. Accurate Shader Multiplication now has Auto, the default.
- New option Graphics > Accurate Barriers (Vulkan), standalone's, on by default.
- The Skylanders, Disney Infinity and LEGO Dimensions add-on options are shown only while one of their games is loaded, below all categories.
- Graphics is Graphics (Restart): its options apply once the game is started again, except GX2DrawDone Sync and Accurate Barriers, whose help says they can be toggled during gameplay. An option for one graphics API says which in its name: Precompiled Shaders (OpenGL), Async Shader Compile (Vulkan), Accurate Barriers (Vulkan) (NNshi).
- Vulkan is the default graphics API, as in standalone Cemu (NNshi).
- Upscale Filter and Downscale Filter removed: they acted only on the GamePad picture in the composite screen layouts, never on the TV picture RetroArch scales (NNshi).
- Frame Wait removed: each run waits the whole frame time for the game's frame, as the default did. Waiting 72 % of it made no measurable difference on a PC or a phone (NNshi, sco8487).
- Internal Resolution is no longer hidden while a resolution graphic pack is on (NNshi).
- Show Game FPS is under Core, at the bottom: it shows the game's own frame rate where RetroArch's counter does not (NNshi).
- Options the core hides (the screen layout slots above Number of Screen Layouts) are hidden again right after the options are declared anew, which happens at a game's start; they showed in the menu until another option was changed (NNshi).
- Start Conversion to WUA is also offered for a `.wua` that lacks an installed update or DLC, or has an older version of one: a new `.wua` is written with them. Its help text says which of the three cases it is: the game alone, the game with its update and DLC, or a `.wua` to add them to. An existing file is never replaced; a taken name gets a number after it, where the conversion used to overwrite a `.wua` of the same name (sco8487).
- Sound: each frame hands RetroArch one frame's worth of audio, as other cores do, and more only to work off a backlog. It handed over whatever the game had made by the end of the frame, a different amount every frame, so RetroArch's audio buffer swung between blocking and running dry without settling (NNshi).
- Sound: the game's audio frames are made at the console's pace, one every 3 ms, and faster only to catch up. At 30 fps each frame's 33 ms of audio was made in a 19 ms burst followed by a 14 ms gap, so streaming voices were fed unevenly, with pops and crackles standalone Cemu does not have (NNshi, Wind Waker HD).

## October 2026

### Upstream

- Merged up to upstream Cemu 2.6-356 (aa20e2f8), after the merge of 3 October (32e6628a, Latte shader and texture fixes). The core reports upstream's version.

### Sound and pads

- GamePad Motion option (System, off by default as in standalone): the GamePad's gyroscope and accelerometer come from the sensors RetroArch reads on port 1, for games that aim or steer by tilting the GamePad. On Linux with the udev controller driver, a DualSense or DualShock 4 needs its motion sensors device made readable; the README has the rule (tested by Shoegzer, Splatoon with a DualSense).

### Picture

- Internal Resolution as multiples of the game's own resolution (0.25x to 3x), with 16:9 render targets kept 16:9. The largest picture RetroArch is told to expect grows with it.
- The frame rate is always the graphic packs'; there is no Frame Rate option.
- A 30 fps game is reported to RetroArch as 30 fps: the core follows the game's own swap interval (GX2SetSwapInterval) once it has held for a second, where it reported 60 and showed every frame twice, unevenly (NNshi, Wind Waker HD).
- New option Video > Frame Wait: how long each run waits for the game's frame. Whole Frame, the default, gives the GPU the whole frame time as standalone Cemu does; Most of a Frame waits 72 % of it, as the core did before.
- New option Video > Render Ahead One Frame (off by default): the GPU draws the next frame while RetroArch presents the last, for one frame more latency, as standalone Cemu's swapchain has.
- Vulkan: a frame is handed to RetroArch only once its copy has been submitted; before, RetroArch could show the previous frame again (a repeated and a dropped frame, NNshi, Mario Kart 8).
- The Wii U's software keyboard (Wind Waker HD's name, for one) is typed into with RetroArch's keyboard (Game Focus on), the text shown in RetroArch's notifications; Start on the pad accepts, with the account's name when nothing was typed. Before, the game waited on a keyboard nobody could see.
- The pipeline cache keeps every pipeline compiled before the game was closed; the last ones were lost and compiled again at every start (NNshi, the same stutters in BotW and Mario Kart 8 each session).
- OpenGL shows both screens in the composite layouts.
- Android: Taiko's Don is drawn on Qualcomm's driver.

### Games and content

- New option Accounts > Rename Active Account: the account's name is entered inside the core, with a pad (Up and Down change the last character, Right adds one, Left removes one, Start accepts, Select cancels) or a keyboard, and shown as the frontend's status message while it is typed. `account_name.txt` is written with the new name. It needs the frontend's on-screen notifications on (Shoegzer, #28).
- Accounts can be named: `system/Cemu/account_name.txt` has a line per account, `<id> = <name>`, up to ten characters; the core writes the file with the accounts there are (at each title start and when an account is made or removed), each takes its name from it when a title starts, and the account lists in the options show it (Shoegzer #28, NNshi).
- Manage Content: Install Game and Uninstall Game, for the running game, into mlc01. Updates and DLC are installed from `system/Cemu/titles`, and installed content can be removed.
- Disc images have their keys beside them (`<image>.key`).
- Graphic packs: an Enabled switch per pack, with preset groups shown as standalone does.

### Stability

- Linux: the core no longer links libGL and libX11, so it loads on a system without X11. The GLX functions it shares RetroArch's OpenGL context with on an X11 session are found at run time, in RetroArch's own libraries.
- RetroArch can unload the core: the audio API and the graphic pack loading run on joined threads, the GPU thread ends properly on Windows, and unloaded modules are forgotten by the graphic packs, padscore and the DLC list.

### Options and logging

- Log Thread CPU Time: how busy each emulated core's thread, the GPU thread and the frontend's thread were, once a second; on Linux and Android also each core's clock against its maximum.
- A Dump Shaders option. Logging is the last category.
- Options that need a restart say so at the end of their description.
